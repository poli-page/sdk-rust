Every fallible operation in the crate returns `Result<T, poli_page::Error>`. The error enum splits cleanly into SDK-internal variants (no wire `code`) and API-status variants (carrying `status`, `code`, `message`, and `request_id`).

## The Error enum

```rust
use poli_page::{Error, PoliPage, RenderInput};
use serde_json::json;

#[tokio::main]
async fn main() {
    let client = PoliPage::new(std::env::var("POLI_PAGE_API_KEY").unwrap()).unwrap();

    let input = RenderInput {
        project: "getting-started".into(),
        template: "welcome".into(),
        data: json!({ "name": "SDK Demo" }),
        ..Default::default()
    };

    match client.render.pdf(input).await {
        Ok(pdf) => { let _ = pdf; }
        Err(err) => match err {
            Error::Auth { request_id, .. } => eprintln!("auth failed; req {:?}", request_id),
            Error::RateLimited { .. } => eprintln!("rate limited"),
            other => eprintln!("{}: {}", other.code(), other),
        },
    }
}
```

`Error` is `#[non_exhaustive]` — always include a catch-all arm so future variants don't break your match.

## Convenience predicates

For cross-language parity the enum exposes `is_auth_error()`, `is_rate_limit_error()`, `is_validation_error()`, `is_network_error()`, and `is_retryable()`. Use them when you don't need to bind the inner fields. They read the status, the same in every Poli Page SDK: `is_auth_error()` is status 401 or 403 (a `DOWNLOAD_FAILED` refused with 403 too), `is_rate_limit_error()` 429, `is_validation_error()` 400 only (an `Error::BadRequest` with 422 is not one), `is_network_error()` is `network_error` or `timeout`, and `is_retryable()` is what the SDK retries: a network error, a timeout, a 5xx or a 429, except `QUOTA_EXCEEDED`, `OVERAGE_CAP_EXCEEDED` and `STORAGE_ACCESS_DENIED`; never `aborted` or `DOWNLOAD_FAILED`.

`err.message()` is the bare explanation. For SDK-side errors it is the exact text below, the same in every Poli Page SDK, and `Display` shows it as is; for API errors it is the body's `detail`, `title` or `message`, else `HTTP <status>`, and `Display` adds the kind and status (`not found (404): …`). The transport error behind a network or download failure, and the read error behind a malformed error body, is the error's `source()`; `Error::Timeout` has no source.

## Example

```rust
use poli_page::{Error, PoliPage, RenderInput};
use serde_json::json;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let client = PoliPage::new(std::env::var("POLI_PAGE_API_KEY")?)?;

    let input = RenderInput {
        project: "billing".into(),
        template: "invoice".into(),
        data: json!({ "invoiceNumber": "INV-001" }),
        ..Default::default()
    };

    match client.render.pdf(input).await {
        Ok(_pdf) => {}
        Err(Error::RateLimited { request_id, .. }) => {
            eprintln!("rate limited (req {:?}) — back off", request_id);
            return Ok(());
        }
        Err(err) => return Err(err.into()),
    }
    Ok(())
}
```
