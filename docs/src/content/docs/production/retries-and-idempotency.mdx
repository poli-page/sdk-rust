---
title: Retries and idempotency
description: How the Rust SDK retries transient failures and how to make your render calls safe to retry.
---

The Poli Page Rust SDK retries transient failures automatically. Every POST carries an auto-generated UUID v4 idempotency key, the same on every retry of one call. The API does not deduplicate on that key, so a retried render can store a second document (see [Idempotency](#idempotency)).

## Default retry policy

- `Error::Connection` (`network_error`), `Error::Timeout`, 5xx responses (including `503 PUBLISH_IN_PROGRESS` while a publish holds the project) and 429 (`RateLimited`) are retried.
- Except `QUOTA_EXCEEDED`, `OVERAGE_CAP_EXCEEDED` (429) and `STORAGE_ACCESS_DENIED` (502): waiting cannot fix them (they last until the monthly reset, or until the bucket access is restored), so they are returned at once and `is_retryable()` is `false`.
- At most `1 + max_retries` attempts (default `2` — three total attempts); the last error is returned.
- Before retry `n` (1-based) the SDK waits `retry_delay × 2^(n−1) × j`, with `j` a random factor in `[0.5, 1.5)` (default `retry_delay` 500 ms). The wait is never shorter than that delay.
- A `Retry-After` header (integer seconds or HTTP-date) replaces that delay, without jitter, clamped to 0–30 s: `Retry-After: 0` or a past date retries at once, a longer `Retry-After` is retried after 30 s and can use up `max_retries`. Any other value falls back to the backoff. `Retry-After-Ms` is ignored.
- `Error::Aborted` is never retried, and neither is the presigned-URL download (`DOWNLOAD_FAILED`, whatever the storage status).

## Timeouts

`timeout` (default 60 s) bounds each attempt, not the whole call: one deadline covers the connection, the request, the answer and its whole body, also when you inject your own `reqwest::Client`. An answer whose body is cut off is a `network_error`, one whose body outlasts the deadline a `timeout`; both are retried.

## No hidden resend

Every request the server receives is one of the SDK's attempts: counted by `max_retries` and reported to `on_request`. The SDK's own `reqwest` client turns off reqwest's retry policy, which would resend a request the server refused over HTTP/2. If you inject a client with `http_client(...)`, build it with `.retry(reqwest::retry::never())` too.

## Disabling retries

Set `max_retries(0)` on the builder to disable retries entirely:

```rust
use poli_page::PoliPage;

let client = PoliPage::builder()
    .api_key(std::env::var("POLI_PAGE_API_KEY").unwrap())
    .max_retries(0)
    .build()
    .unwrap();
```

## Idempotency

Every POST (renders and thumbnails) includes a UUID v4 `Idempotency-Key` header generated by the SDK, the same on every attempt of one call. The API does not deduplicate on this header, and every render creates a new document: a retry can store a second document whenever the first attempt was stored but its answer was lost, after a 5xx raised once the document was stored, a `timeout` that fired while the API was still rendering, or a `network_error` after the request reached the API. A `503 PUBLISH_IN_PROGRESS` is raised before any render work, so retrying it never duplicates.

You can still supply your own key on the input, for example to correlate a call in your logs:

```rust
use poli_page::RenderInput;
use serde_json::json;

let input = RenderInput {
    project: "billing".into(),
    template: "invoice".into(),
    data: json!({ "invoiceNumber": "INV-001" }),
    idempotency_key: Some("invoice-INV-001-v1".into()),
    ..Default::default()
};
```

The key is sent as is on every attempt; it does not make the render idempotent.

## Example

```rust
use poli_page::{PoliPage, RenderInput};
use serde_json::json;
use std::time::Duration;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let client = PoliPage::builder()
        .api_key(std::env::var("POLI_PAGE_API_KEY")?)
        .max_retries(4)
        .retry_delay(Duration::from_millis(250))
        .build()?;

    let _pdf = client.render.pdf(RenderInput {
        project: "billing".into(),
        template: "invoice".into(),
        data: json!({ "invoiceNumber": "INV-001" }),
        ..Default::default()
    }).await?;

    Ok(())
}
```
